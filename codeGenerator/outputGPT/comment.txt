I changed the invoice accounting update logic in `updateSAPPayment_updateRequestPayments.esql` to split the previous unconditional SAP-error handling into the two requested branches:

- SAP status not empty + Salesforce status = `Posted`  
  -> update `Status = 'In progress'` and set `IntegrationMessage__c` / `IntegrationCode__c`
- SAP status not empty + Salesforce status <> `Posted`  
  -> update only `IntegrationMessage__c` / `IntegrationCode__c`

To keep the implementation consistent with the existing design, I also added a new policy template `PaymentRequest_Error_InProgress` in `Common.policyxml`, and the ESQL now selects between that new template and the existing `PaymentRequest_Error` template.

Assumption made:
- The correct place to implement this request is the invoices application module `updateSAPPayment_updateRequestPayments.esql`, because that is where the existing “SAP status not empty” invoice-accounting logic already exists.
- The comparison for Salesforce status remains case-insensitive via the existing `UPPER(...) = 'POSTED'` logic.
- The requested target status string is exactly `In progress`.

I did not change any flows or descriptors because the existing node wiring already points to the same ESQL module and no additional artifacts were required.
