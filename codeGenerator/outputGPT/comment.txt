Updated the invoice acknowledgment update logic to implement the new 3a/3b behavior.

What changed:
- In `updateSAPPayment_updateRequestPayments.esql`
  - Added conditional handling for records where SAP status is not empty:
    - If Salesforce status is `Posted`, the update now sets:
      - `Id`
      - `Status = 'In progress'`
      - `IntegrationMessage__c`
      - `IntegrationCode__c`
    - If Salesforce status is not `Posted`, the update now sets:
      - `Id`
      - `IntegrationMessage__c`
      - `IntegrationCode__c`
  - Added tracking for invoices already handled by SAP-error logic so they are not also processed later by the “invalid status” branch. This avoids contradictory duplicate updates and preserves the requested SAP error message/code.
- In `Common.policyxml`
  - Added a new policy template: `PaymentRequest_Error_InProgress`

Assumption made:
- I assumed records handled by the new 3a/3b SAP-error logic must not also be treated as “invalid status” records later in the same flow, because that later branch would overwrite the requested SAP error mapping and conflict with the new requirement.

Limitations:
- I did not change other payment-related shared-library flows because the provided request and the existing local application logic clearly point to the invoice acknowledgment flow in this application.
