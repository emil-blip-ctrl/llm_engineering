## Why

`finance-accounting-integration-invoices-ingestion` today has three near-identical per-company injection subflows (`postAsv_`/`postSarge_`/`postSarvd_files_injection_trigger.subflow`). Sansys needs **one generic subflow** serving all 6 companies (company travels in the payload, not in the flow name), and its mapper must emit **EOM v2 camelCase** rather than the v1 kebab-case shape the Attrib mappers produce.

Three structural changes distinguish this from a copy-paste of the ASV subflow:

1. **Batch, not one-file-per-trigger.** The current `ComIbmFileRead` consumes one file per trigger invocation. This story replaces that with a whole-folder batch — and a queue is explicitly forbidden.
2. **Validation must stop requiring** `fip_number`. Sansys never sends it. The relaxation must be keyed on **source/trigger**, not company — `TAG`/`TAV`/`ASV` dual-run both front-ends and Attrib must keep enforcing it.
3. **Identity is derived, not received.** Sansys sends no `object_system`; `bukrs` is transcoded from `intervention.base_id` via the base-identity lookup (see [Cross Cuttings](https://tcsgroup.atlassian.net/wiki/spaces/CS/pages/2265907431)). `producer_app` is **not** handled here — it is a hardcoded constant in [NIPO-9499](https://tcsgroup.atlassian.net/wiki/spaces/ARCHI/pages/2233008237/US+NIPO-9499+Sansys+-+Financial+Document+V2+to+S_FIN_DOC).

## What

- **One** generic `postSansys_files_injection_trigger.subflow` — not six.
- A **whole-folder batch** read: one trigger drains every `*.json` in the Sansys `/input`, no message queue anywhere in the loop.
- A generic Sansys mapper (`sansys/PrepareReceivableDocumentRequest.esql`) emitting EOM v2 camelCase per the `SANSYS => EOM` sheet — including both `invoiceNumber` entries (`INVOICE_ID` ← `id`, `TRANSPORT_NUMBER` ← `intervention.references[]`) and `processControl.specificationIdentifier = 'AMBULANCE_TRANSPORT_BILLING'`.
- `bukrs` derived from `intervention.base_id`, carried as `seller.sellerIdentifier[].schemeIdentifier = 'COMPANY_CODE'`.
- A Sansys-shaped validation variant: `fip_number` no longer required; `category_id`/`category_name` still required; `intervention.references[TRANSPORT_NUMBER]` newly required. Attrib's validation byte-identical to today.
- `save/` on consumption, `done/`/`errors/` on outcome — same policy properties, per file.
- The 3 Attrib subflows, their 3 mappers, and `/health` unchanged.

**Definition of done:** one trigger against a Sansys `/input` holding *n* files leaves `/input` empty, *n* copies in `save/`, each file's valid invoices in a `done/` payload accepted by the downstream v2 posting path, invalid invoices in `errors/` — with the 3 Attrib flows provably untouched.

**Batch-loop options (task 3 — dev's choice, all queue-free):**

| **Option** | **How** | **Trade-off** |
| --- | --- | --- |
| **A — loop the destructive** `FileRead` (recommended) | Re-enter `FileRead` (`*.json`) until `noMatch`; each read archives + deletes its file | Smallest delta from today. Needs an iteration cap so a folder being written into cannot spin the flow. |
| B — list, then loop | List the directory once, iterate names, `FileRead` each by exact name | Batch size known up front (truthful `receivedCount`); more moving parts. |
| C — `FileInput` node | ACE polls the directory | **Rejected**: the trigger stops controlling when ingestion runs, breaking the VTOM cadence. |

**v1 → v2 mapper delta (task 7)** — same semantics, different casing and identity source:

| Concern | v1 (`asv/PrepareHTTPRequest.esql`) | v2 (Sansys, this story) |
| --- | --- | --- |
| Key casing | kebab-case (`"invoice-number"`) | camelCase (`invoiceNumber`) |
| `process_control` | `'ASV_INTERVENTION_CUSTOMER_BILLING'`, hardcoded per company | `'AMBULANCE_TRANSPORT_BILLING'`, one value for all 6 |
| Invoice identity #1 | `id` → `'INVOICE_ID'` | unchanged in meaning |
