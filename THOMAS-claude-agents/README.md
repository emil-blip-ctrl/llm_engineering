# Agentic-Claude

![CI](https://github.com/Aletheia-Thomas/Claude-Agents/actions/workflows/validate.yml/badge.svg)
![Version](https://img.shields.io/badge/version-v1.2-blue)
![License](https://img.shields.io/badge/license-MIT-green)

Reusable agent definitions, skills, and team compositions for [Claude Code](https://claude.ai/code). Drop them into any project to get specialized AI roles with enforced boundaries, persistent memory, and orchestrated multi-agent workflows.

---

## What's included

| Type | Contents |
|------|----------|
| **8 agents** | `developer`, `tester`, `devops`, `documentarian`, `architect`, `product-owner-assistant`, `librarian`, `library-engineer` |
| **7 skills** | `/develop`, `/test`, `/deploy`, `/review`, `/document`, `/postman-collection-generator`, `/publish-confluence` |
| **4 teams** | `feature-team`, `release-team`, `full-team`, `repo-improvement-team` |

Each agent has a defined role, a minimal tool set, and `memory: project` — it learns patterns within your project without leaking to others.

---

## Quick start

**Windows (one command):**
```powershell
powershell -ExecutionPolicy Bypass -File templates/setup.ps1
```

**Mac/Linux:**
```bash
bash templates/setup.sh
```

Both scripts install everything into your project: agents, skills, VS Code workspace, hooks, CLAUDE.md template, and `.gitignore` entries. Run interactively (asks for project path) or pass `--project-path /path/to/project --silent` for CI.

**Or via Claude Code plugin (pinned version):**
```
/plugin marketplace add Aletheia-Thomas/Claude-Agents
/plugin install agentic-claude@agentic-claude-lib
```

See [`docs/howto/PLUGIN-SETUP.md`](docs/howto/PLUGIN-SETUP.md) for the full installation guide including version pinning.

## Agents at a glance

| Agent | Model | What it does |
|-------|-------|-------------|
| `developer` | Opus 4.8 | Writes production code (SOLID, Clean Code). Never tests or deploys. |
| `tester` | Opus 4.8 | Writes and runs tests (ISTQB). Never touches production code. |
| `devops` | Opus 4.8 | CI/CD, Docker, Azure, SBOM. No app code or tests. |
| `documentarian` | Sonnet 4.6 | Keeps CLAUDE.md, ADRs, and docs in sync. No code. |
| `architect` | Opus 4.8 | Maps IBM APIC/ACE/MQ integration dependencies. No implementation. |
| `product-owner-assistant` | Opus 4.8 | Orchestrates other agents. Manages backlog. Never codes. |
| `librarian` | Opus 4.8 | Maintains this library's definitions and docs. Repo-internal only. |
| `library-engineer` | Opus 4.8 | Maintains this library's scripts and hooks. Repo-internal only. |

## Teams

| Team | Agents | Use for |
|------|--------|---------|
| `feature-team` | developer → tester → documentarian | Implementing a feature end-to-end |
| `release-team` | tester → devops → documentarian | Preparing and validating a release |
| `full-team` | all 6 project agents (PO orchestrates) | Major features, migrations, bootstrapping |
| `repo-improvement-team` | PO + librarian + library-engineer | Improving this library itself |

To use teams, open a multi-root VS Code workspace (generated by `setup.ps1`) and enable:
```bash
export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1
```

## Keeping models up to date

When Anthropic releases new Claude models, run:

```powershell
# Windows — dry-run first, then apply
powershell -ExecutionPolicy Bypass -File templates/update.ps1
powershell -ExecutionPolicy Bypass -File templates/update.ps1 -Apply
```
```bash
# Mac/Linux
bash templates/update.sh
bash templates/update.sh --apply
```

Or validate locally before pushing:
```bash
python3 scripts/validate_agents.py --strict
```

The same checks run automatically on every push via `.github/workflows/validate.yml`.

## Hooks

`templates/settings.json` ships with hooks that enforce good practices:

- **PreToolUse** — blocks direct `git push` to `main`/`master`
- **PostToolUse** — reminds to run `/test` after file edits, reminds to push after a commit
- **SubagentStop** — after each agent completes, prompts the next step in the workflow
- **Notification** — logs all Claude notifications to `.claude/memory/notifications.log`
- **Stop** — end-of-session reminder (commit, `/test`, `/document`)

## Marketplace

This repo acts as a Claude Code marketplace. Any team can add it as a source and install plugins from it.

### Register the marketplace (once per machine)

```
/plugin marketplace add Aletheia-Thomas/Claude-Agents
```

> **GitLab:** replace with `https://git-scm.tcsgroup.ch/<group>/Claude-Agents` when the repo moves.

### Install the plugin

```
/plugin install agentic-claude@agentic-claude-lib
```

### Pin a specific version for a project

Add to the project's `.claude/settings.json`:

```jsonc
{
  "extraKnownMarketplaces": {
    "agentic-claude-lib": {
      "source": { "source": "github", "repo": "Aletheia-Thomas/Claude-Agents" }
    }
  },
  "enabledPlugins": [ "agentic-claude@agentic-claude-lib" ]
}
```

Different projects can pin different versions simultaneously — project scope overrides user scope.

## Publish to Confluence

The script `scripts/publish_to_confluence.py` publishes documentation to Confluence. It supports two independent modes.

### Required environment variables

```bash
export CONFLUENCE_BASE_URL="https://confluence.tcsgroup.ch"
export CONFLUENCE_SPACE_KEY="ARCH"
export CONFLUENCE_API_TOKEN="your-token"
export CONFLUENCE_USER="your.email@tcs.ch"       # for basic auth
```

### Mode 1 — Publish the presentation

Publishes `docs/presentation/index.html` as a single Confluence page.

```bash
PUBLISH_PRESENTATION=true python3 scripts/publish_to_confluence.py
```

### Mode 2 — Publish the docs (guides + hooks + changelog)

Publishes Markdown files as child Confluence pages:
- `CHANGELOG.md`
- `docs/howto/PLUGIN-SETUP.md`
- `docs/howto/AGENT-AUTHORING.md`
- `docs/howto/SKILL-AUTHORING.md`
- `docs/howto/TEAM-AUTHORING.md`
- Auto-generated **Hooks & Guardrails** page from `.claude/settings.json` and `.claude/hooks/`

```bash
PUBLISH_DOCS=true python3 scripts/publish_to_confluence.py
```

Nest the doc pages under a specific Confluence page:

```bash
PUBLISH_DOCS=true CONFLUENCE_DOCS_PARENT_ID=123456 python3 scripts/publish_to_confluence.py
```

### Publish everything at once

```bash
PUBLISH_PRESENTATION=true PUBLISH_DOCS=true python3 scripts/publish_to_confluence.py
```

### Dry run (no API calls)

```bash
DRY_RUN=true PUBLISH_DOCS=true python3 scripts/publish_to_confluence.py
# Output written to docs/.preview/
```

### Full list of environment variables

| Variable | Default | Description |
|----------|---------|-------------|
| `CONFLUENCE_BASE_URL` | — | Required. Base URL of your Confluence instance |
| `CONFLUENCE_SPACE_KEY` | — | Required. Target space key (e.g. `ARCH`) |
| `CONFLUENCE_API_TOKEN` | — | Required. API token or Personal Access Token |
| `CONFLUENCE_USER` | — | Account email (required for basic auth) |
| `CONFLUENCE_AUTH` | `basic` | `basic` or `bearer` (Server/DC PAT) |
| `CONFLUENCE_PARENT_ID` | — | Parent page ID for all published pages |
| `CONFLUENCE_DOCS_PARENT_ID` | same as above | Override parent for docs-mode pages |
| `CONFLUENCE_PAGE_TITLE` | `Agentic-Claude — Agent & Skill Library` | Title for the presentation page |
| `CONFLUENCE_RESTRICT` | `true` | Lock pages to read-only after publish |
| `PRESENTATION_HTML` | `docs/presentation/index.html` | Path to the source HTML |
| `PUBLISH_PRESENTATION` | `true` | Publish the presentation page |
| `PUBLISH_DOCS` | `false` | Publish Markdown docs as child pages |
| `DRY_RUN` | `false` | Write output locally, no API calls |
